# API Contract - Notification Service

Base path: `/notifications`

All responses are `application/json`. Errors follow the shape:
```json
{ "error": "human-readable message" }
```

All endpoints require `Authorization: Bearer <access_token>`.

The Notification Service is **purely reactive** - it never initiates actions. It only consumes RabbitMQ events and exposes HTTP endpoints for clients to read/mark notifications.

> **ID policy:** all IDs are Snowflake `BIGINT`s generated by the service. On the JSON wire they appear as quoted strings (e.g. `"123456789012345678"`) so JS clients can hold them without precision loss.

---

## REST Endpoints

### GET /notifications

Fetch notifications for the authenticated user. Dismissed notifications are excluded by default - they have been removed from the panel and are not meant to come back unless explicitly requested.

**Query params:**
| Param | Type | Description |
|-------|------|-------------|
| `read` | bool | Filter by read status. `false` = unread only. Omit for all. |
| `include_dismissed` | bool | If `true`, also return notifications the user has dismissed. Default `false`. |
| `limit` | int | Max results (default 50, max 100) |
| `before` | snowflake | Cursor for pagination |

**Response `200`:**
```json
[
  {
    "id": "<snowflake>",
    "user_id": "<snowflake>",
    "type": "mention",
    "actor_id": "<snowflake>",
    "source_id": "<snowflake>",
    "payload": {
      "channel_id": "<snowflake>",
      "guild_id": "<snowflake>",
      "preview": "T'es mauvais @yandry"
    },
    "read": false,
    "dismissed_at": null,
    "created_at": "2026-03-09T12:00:00Z"
  }
]
```

`dismissed_at` is `null` for active notifications and an ISO 8601 timestamp once the user dismisses them (see `DELETE /notifications/{id}`).

`actor_id` and `source_id` are top-level fields backed by dedicated columns (see `docs/schema/notification.sql`):
- `actor_id`: the user who caused this notification (used for blocked-user suppression). NULL for system events.
- `source_id`: the entity this notification deep-links to (a message, friendship, guild, etc.). NULL when there is no persistent target.

**Notification types - what each field carries:**

| `type` | `actor_id` | `source_id` | `payload` |
|--------|------------|-------------|-----------|
| `mention` | `author_id` of the message | `message_id` | `{ channel_id, guild_id, preview }` |
| `dm` | `sender_id` | `message_id` | `{ conversation_id, preview }` |
| `friend_request` | `requester_id` | friendship row id | `{}` |
| `guild_invite` | `invited_by_user_id` | `guild_id` | `{ guild_name }` |
| `guild_welcome` | NULL (system event) | `guild_id` | `{ guild_name }` |
| `incoming_call` | `caller_id` | NULL (call is ephemeral) | `{ call_type: "audio" \| "video" }` |

### PATCH /notifications/{id}/read

Mark a single notification as read.

**Request body:** None

**Response `200`:**
```json
{
  "id": "<snowflake>",
  "read": true
}
```

**Errors:**
| Status | Reason |
|--------|--------|
| 403 | Notification does not belong to this user |
| 404 | Notification not found |

---

### PATCH /notifications/read-all

Mark all notifications as read for the authenticated user.

**Request body:** None

**Response `200`:**
```json
{
  "updated": 12
}
```

---

### DELETE /notifications/{id}

Dismiss a notification. Soft-delete: the row stays in DB with `dismissed_at` set so it does not reappear in the panel, but `include_dismissed=true` on `GET /notifications` can still surface it.

**Response `204`:** No content.

**Errors:**
| Status | Reason |
|--------|--------|
| 403 | Notification does not belong to this user |
| 404 | Notification not found |

## SignalR - Real-time delivery

The Notification Service pushes real-time alerts via SignalR (either its own hub or shared with Chat Service - implementation detail). When a notification is created for a user who is currently connected, the service immediately pushes it:

**Server → Client event: `ReceiveNotification`**

The payload is identical to a single element of the `GET /notifications` response (minus `user_id`, which is implicit from the connection).

```json
{
  "target": "ReceiveNotification",
  "arguments": [{
    "id": "<snowflake>",
    "type": "mention",
    "actor_id": "<snowflake>",
    "source_id": "<snowflake>",
    "payload": { "channel_id": "<snowflake>", "guild_id": "<snowflake>", "preview": "..." },
    "read": false,
    "created_at": "2026-03-09T12:00:00Z"
  }]
}
```

If the user is not connected, the notification row stays in DB and is fetched on next login via `GET /notifications?read=false`.

## Preferences Endpoints

Per-user mute settings for guilds and channels. Backed by `notification_preferences` (`docs/schema/notification.sql`). Before inserting a notification, the Notification Service checks whether the target user has a matching unexpired mute and skips the insert if so.

`scope_type` must be one of `guild` or `channel`. `scope_id` is the snowflake of the guild or channel.

### GET /notifications/preferences

List all preferences the caller has set. Defaults (no row) are not included - omission means "not muted".

**Response `200`:**
```json
[
  {
    "scope_type": "guild",
    "scope_id": "<snowflake>",
    "muted": true,
    "muted_until": "2026-03-10T00:00:00Z"
  }
]
```

`muted_until` is `null` for indefinite mutes.

---

### PUT /notifications/preferences/{scope_type}/{scope_id}

Create or update a preference for one scope.

**Request body:**
```json
{
  "muted": true,
  "muted_until": "2026-03-10T00:00:00Z"
}
```

`muted_until` is optional; omit (or `null`) for an indefinite mute. Setting `muted: false` keeps the row but disables muting - useful if a future default changes.

**Response `200`:** Updated preference object (same shape as the GET list entry).

**Errors:**
| Status | Reason |
|--------|--------|
| 400 | Invalid `scope_type`, or `muted_until` in the past |

---

### DELETE /notifications/preferences/{scope_type}/{scope_id}

Remove the preference, reverting the scope to default behavior (unmuted).

**Response `204`:** No content.

**Errors:**
| Status | Reason |
|--------|--------|
| 404 | No preference set for this scope |

## RabbitMQ Events Consumed

| Event | Trigger | Notification created |
|-------|---------|---------------------|
| `chat.message_sent` | User is in `mentions[]` | `type: mention` for each mentioned user |
| `chat.dm_sent` | Always | `type: dm` for `recipient_id` |
| `call.incoming` | Always | `type: incoming_call` for `callee_id` - prompts them to open the app |
| `friend.request_sent` | Always | `type: friend_request` for `addressee_id` |
| `guild.invite_created` | `invited_user_id` is present | `type: guild_invite` for `invited_user_id` |
| `guild.member_joined` | Always | `type: guild_welcome` for the joining user |
| `user.deleted` | Always | Delete every notification row where `user_id` or `actor_id` matches the deleted user. Also drop the user's `notification_preferences` rows. |
